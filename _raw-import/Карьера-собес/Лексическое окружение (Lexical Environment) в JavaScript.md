**Лексическое окружение** — это концепция, которая описывает, как [JavaScript](../Работа/JavaScript) хранит и ищет переменные, функции и их значения в текущем контексте выполнения. Оно создается при запуске функции, блока кода или глобального контекста.

---

**Основные концепции:**

**1. **Лексическое окружение****

Лексическое окружение — это структура данных, которая содержит:

- **Переменные** и их значения.
- Ссылку на внешнее (родительское) лексическое окружение.

Каждое лексическое окружение состоит из двух частей:

1. **Environment Record (Запись окружения)** — хранит локальные переменные и функции текущего выполнения.
2. **Outer Environment Reference (Ссылка на внешнее окружение)** — указывает на лексическое окружение родительского уровня.

**2. **Типы окружений****

- **Глобальное лексическое окружение** Создается при запуске скрипта. Хранит глобальные переменные и функции.
- **Функциональное лексическое окружение** Создается при вызове функции. Хранит локальные переменные и аргументы.
- **Блочное лексическое окружение** Создается для блоков кода, таких как `if`, `for`, `while`, при использовании `let` и `const`.

---

**Пример:**

```javascript
let a = 10;

function outer() {
    let b = 20;

    function inner() {
        let c = 30;
        console.log(a + b + c); // Доступ ко всем уровням окружения
    }

    inner();
}

outer();
```

**Порядок выполнения:**

1. **Глобальное лексическое окружение:**
    
    - `a = 10`
    - `outer = function`
2. **Лексическое окружение функции `outer`:**
    
    - `b = 20`
    - `inner = function`
3. **Лексическое окружение функции `inner`:**
    
    - `c = 30`

Каждая функция имеет доступ к своему лексическому окружению **и** окружению вышестоящих уровней через **ссылку на родителя**.

---

****Scope (Область видимости)** и лексическое окружение**

- **Область видимости (Scope)** — это видимая часть программы, где можно использовать переменную.
- **Лексическое окружение** определяет, какие переменные доступны функции в зависимости от места ее объявления.

**Пример:**

```javascript
function example() {
    let x = 10;
    if (true) {
        let y = 20;
        console.log(x); // Видит x
        console.log(y); // Видит y
    }
    console.log(y); // Ошибка: y не определена
}
```

Переменная `y` недоступна за пределами блока, потому что `let` создает блочное окружение.

---

**Закрытия (Closures) и лексическое окружение**

Закрытие — это функция, которая «захватывает» переменные из своего внешнего окружения даже после завершения его выполнения.

**Пример:**

```javascript
function createCounter() {
    let count = 0;

    return function () {
        count++;
        return count;
    };
}

const counter = createCounter();

console.log(counter()); // 1
console.log(counter()); // 2
```

- Лексическое окружение функции `createCounter` не уничтожается после ее завершения, так как функция, возвращенная из нее, продолжает ссылаться на это окружение.

---

**Важные моменты:**

1. **Лексическое окружение создается в момент вызова функции или выполнения блока.**
2. **Лексическое окружение "живет" столько, сколько есть ссылки на него.**
3. **Переменные, объявленные через `var`, не ограничены блочной областью видимости, в отличие от `let` и `const`.**

**Пример:**

```javascript
if (true) {
    var x = 10;
    let y = 20;
}

console.log(x); // 10
console.log(y); // Ошибка: y не определена
```

---

**Взаимодействие Event Loop с лексическим окружением**

Лексическое окружение играет важную роль при обработке асинхронного кода. Например, в замыканиях с `setTimeout`:

```javascript
for (let i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100);
}
// Вывод: 0, 1, 2
```

Если заменить `let` на `var`:

```javascript
for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100);
}
// Вывод: 3, 3, 3
```

`var` не создает новое лексическое окружение для каждой итерации, а `let` — создает.

---

**Лексическое окружение — это основа работы с областью видимости, замыканиями и контекстом исполнения в JavaScript. Понимание этой концепции помогает эффективно разрабатывать сложные и оптимизированные программы.**
