# 🧬 Анатомия промпта

> [← к оглавлению серии](./📌 Введение в промпт-инжиниринг)

После этой заметки ты не будешь «писать как получится» — будешь **собирать** промпт из стандартных деталей, как Lego.

## 6 компонентов хорошего промпта

| # | Компонент | Что отвечает | Обязателен? |
|---|---|---|---|
| 1 | **Роль** (Role) | Кто Claude в этом разговоре | Опционально |
| 2 | **Задача** (Task) | Что нужно сделать | ✅ Всегда |
| 3 | **Контекст** (Context) | Фон, входные данные, твой уровень | Часто да |
| 4 | **Ограничения** (Constraints) | Что нельзя, чего избегать, рамки | По ситуации |
| 5 | **Формат вывода** (Format) | Структура ответа | Сильно желательно |
| 6 | **Примеры** (Examples) | Образцы для подражания | Для сложных задач |

Дальше разбираю каждый — что это и как формулировать.

**1. Роль**

Кратко определяет «оптику», через которую модель смотрит на задачу.

```plain
✅ Ты — senior Vue-разработчик с опытом в крупных продуктовых командах.
❌ Действуй как эксперт.
```

> [!warning]
> Роль **без задачи** — бесполезна. Это не магия, а просто настройка тона. Если задачи нет — пропусти роль.


**2. Задача**

Сердце промпта. Должен быть глагол действия: **объясни / напиши / отрефактори / сравни / найди ошибку / предложи**.

```plain
✅ Отрефактори этот Vue 2 компонент в Composition API на Vue 3.
❌ Помоги с этим компонентом. (помоги ≠ задача)
```

**3. Контекст**

Это самая частая «дыра» в промптах новичков. Контекст отвечает на: **зачем, для кого, в каких условиях**.

```plain
Контекст: это компонент карточки товара в e-commerce проекте.
Используется в каталоге (показывается 50+ раз на странице).
Команда — 3 джуна, читаемость важнее краткости.
```

**4. Ограничения**

То, что задаёт рамки.

```plain
- Не используй внешние библиотеки кроме vue и pinia
- Не больше 100 строк
- Без TypeScript (легаси проект)
- Не объясняй базовый синтаксис, я не новичок
```

> [!tip] Парадокс отрицаний
> Модели **плохо обрабатывают «не делай X»**. Если можешь — переформулируй в позитив:
> - ❌ Не используй var
> - ✅ Используй const / let


**5. Формат вывода**

Тот самый трюк, который даёт +30% к полезности **бесплатно**.

```plain
Формат: дай 3 варианта решения в виде таблицы:
| Вариант | Плюсы | Минусы | Когда применять |

Под таблицей — твоя рекомендация (1 абзац) и код выбранного варианта.
```

Варианты форматов: **таблица, нумерованный список, markdown с заголовками, JSON, код, артефакт, краткий ответ в 2 предложения**.

**6. Примеры (few-shot)**

Когда задача нестандартная или есть специфический формат — покажи 1–2 примера.

```plain
Пример того, как должен выглядеть ответ:
Вход: "useEffect(() => fetch(...))"
Выход: "Используется для side effects. Аналог Vue: watchEffect."

Теперь обработай: "useMemo(() => calc(), [dep])"
```

## Рекомендуемый порядок

```plain
[Роль] → [Задача] → [Контекст] → [Ограничения] → [Формат] → [Примеры] → [Данные]
```

Логика: сначала **кто и что**, потом **обстоятельства**, потом **рамки**, потом **как показать**, в конце — сами **данные**.

> [!important]
> Порядок — не догма. Но если ты новичок — начни именно с него, потом сам поймёшь, где можно отклоняться.


## Большой пример «до / после»

**❌ Было:**

```plain
помоги переписать
```

(дальше прикладывается 200 строк кода)

Что получит: расплывчатый рефакторинг, скорее всего не в том направлении.

**✅ Стало:**

```plain
Ты — senior Vue-разработчик, ревьюишь код джуна.

ЗАДАЧА: переписать прилагаемый компонент с Options API на Composition API.

КОНТЕКСТ: это карточка товара в каталоге. Команда переезжает на Vue 3,
этот компонент — первый в большом рефакторинге, на него будут смотреть
как на пример.

ОГРАНИЧЕНИЯ:
- Composition API через <script setup>
- Никаких внешних библиотек
- Сохрани все события и пропсы, чтобы родительские компоненты не сломались

ФОРМАТ:
1. Готовый код (в артефакте)
2. Под кодом — короткий чек-лист (что изменилось, на что обратить внимание джунам)
3. 1 «гран мудрости» — что в этом коде стоит делать всегда, а что — антипаттерн

КОД:
[вставляешь компонент]
```

Этот промпт даст ответ, который **можно сразу применить**, а не «переписать ещё раз».

## Чек после написания промпта

> [!info]
> 1. Понятно, **кто я** (если важно)?
> 2. Есть **глагол действия**?
> 3. Описан **контекст** (зачем, для кого)?
> 4. Заданы **рамки**?
> 5. Указан **формат**?


Если все 5 — отвечают «да», можно отправлять.
