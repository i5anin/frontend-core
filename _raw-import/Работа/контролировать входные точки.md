- Строго контролировать **входные точки** на каждом уровне (`layer`) и внутри каждого `slice`.
    
- Выносить всю "наружу доступную" логику **только в `index.ts`/`index.js`** на уровне: slice, feature, entity, widget и т.п.
    
- Скрывать внутреннюю реализацию (инкапсуляция, как в модульной архитектуре).
    

Это **абсолютно соответствует принципам FSD и Clean Code**, и реализуется через **публичный интерфейс slice'а через `index`**.

---

## 📁 Как работает `index` в FSD (Public API)

**Принцип:**

> В каждом срезе (`user`, `post`, `comment`), независимо от слоя (`features`, `entities` и т.д.), **весь внешний доступ** к логике, UI, API и моделям должен идти через один файл `index.js`.

---

## 🔐 Цель — инкапсуляция

- **Можно импортировать** только из `index` (`public API`)
    
- **Нельзя импортировать** напрямую `usePostModel.js` или `PostCard.vue` вне среза — только через `entities/post/index.js`
    

---

## ✅ Пример: `entities/post/`

```
entities/
└── post/
    ├── ui/
    │   └── PostCard.vue
    ├── model/
    │   └── usePostModel.js
    ├── api/
    │   └── postApi.js
    └── index.js  ← 👈 Public API
```

**`entities/post/index.js`:**

```js
export { default as PostCard } from './ui/PostCard.vue'
export { usePostModel } from './model/usePostModel'
export { fetchPost } from './api/postApi'
```

---

## 🔒 Использование только через Public API:

```js
// ✅ правильно:
import { PostCard, usePostModel } from '@/entities/post'

// 🚫 плохо: нарушает инкапсуляцию
import PostCard from '@/entities/post/ui/PostCard.vue'
```

---

## 📦 Расширение на все уровни

⛳ Принцип "один вход — один выход" применяется:

|Уровень|Пример пути|Публичный API|
|---|---|---|
|`app`|`src/app/index.js`|Инициализация, обёртки|
|`processes`|`processes/auth/index.js`|Управление auth flow|
|`pages`|`pages/ProfilePage/index.js`|Подготовка страницы|
|`widgets`|`widgets/UserCard/index.js`|Композитный компонент|
|`features`|`features/loginByEmail/index.js`|Хук + UI + actions|
|`entities`|`entities/user/index.js`|Модель, UI, API|
|`shared`|`shared/ui/Button/index.js`|Базовый переиспользуемый UI|

## 🚀 Автоматизация через eslint-plugin

Хочешь гарантировать соблюдение этих правил?

Подключи:

- [`eslint-plugin-fsd`](https://github.com/feature-sliced/eslint-plugin-fsd) с правилом `path-checker`
    
- или напиши свой alias rule, запрещающий `@/entities/user/ui/UserCard.vue`
    

---

## 📌 Вывод

> **Каждый срез, слой и модуль в FSD должен иметь только один "публичный API" через `index.js`, который и используется во внешнем коде.**

Это:

- инкапсулирует детали реализации
    
- уменьшает связанность
    
- упрощает рефакторинг
    

Если хочешь, могу сгенерировать шаблон `fsd-generator`, который будет автоматически создавать структуру с `index.js` на каждом уровне.
