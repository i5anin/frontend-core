****Что такое `tmpfs` в [Docker](./Docker)?****

`tmpfs` (temporary filesystem) — это временная файловая система, которая полностью размещается в оперативной памяти (RAM). Она позволяет контейнерам использовать быстрый и временный доступ к данным, которые не должны сохраняться после остановки контейнера.

---

****Ключевые особенности `tmpfs`:****

1. **Данные хранятся в RAM:**
    
    - Всё содержимое `tmpfs` находится в оперативной памяти, а не на диске.
    - Это делает операции чтения и записи очень быстрыми.
2. **Временность:**
    
    - Данные исчезают при остановке контейнера.
    - Используется для временных данных, которые не нужно сохранять.
3. **Безопасность:**
    
    - Так как данные хранятся в RAM, они автоматически очищаются при остановке контейнера, что делает `tmpfs` полезным для временных конфиденциальных данных.
4. **Нет износа диска:**
    
    - Так как операции происходят в оперативной памяти, это снижает нагрузку на диск и его износ.

---

****Когда использовать `tmpfs`?****

- **Кэширование данных:** Когда контейнеру нужно работать с временными данными, которые часто обновляются.
- **Секреты и ключи:** Для временного хранения чувствительных данных, которые не должны быть сохранены на диск.
- **Ускорение операций:** Для повышения производительности, например, во время выполнения тестов или обработки данных.
- **Приложения с высокой интенсивностью I/O:** Для задач, где критична скорость доступа к данным.

---

****Как использовать `tmpfs` в Docker?****

**1. **При запуске контейнера****

Монтирование `tmpfs` при создании контейнера:

```bash
docker run -d --tmpfs /app/tmp:rw,size=64m my_container
```

- `--tmpfs /app/tmp` — указывает, что каталог `/app/tmp` будет использовать `tmpfs`.
- `rw` — разрешает чтение и запись.
- `size=64m` — ограничивает размер `tmpfs` до 64 MB (по умолчанию доступен весь объём RAM).

---

**2. **Через Docker Compose****

Если ты используешь `docker-compose.yml`, можешь указать `tmpfs` в настройках:

```yaml
services:
  my_service:
    image: my_image
    tmpfs:
      - /app/tmp:rw,size=64m
```

После запуска `docker-compose up` каталог `/app/tmp` будет смонтирован как `tmpfs`.

---

****Команды для проверки `tmpfs`****

1. **Посмотреть монтированные тома у контейнера:**
    
    ```bash
    docker inspect <container_id>
    ```
    
    Ищи раздел `Mounts`:
    
    ```json
    {
        "Destination": "/app/tmp",
        "Type": "tmpfs",
        "Source": "",
        "RW": true
    }
    ```
    
2. **Проверить текущие монтирования в контейнере:** Зайди в контейнер:
    
    ```bash
    docker exec -it <container_id> bash
    ```
    
    И выполни:
    
    ```bash
    mount | grep tmpfs
    ```
    
    Вывод покажет, какие каталоги используют `tmpfs`.
    

---

****Преимущества `tmpfs`:****

- **Высокая скорость:** Быстрее, чем хранение на диске.
- **Автоматическое удаление:** Данные удаляются при остановке контейнера.
- **Снижение износа диска.**

---

****Ограничения `tmpfs`:****

1. **Ограничено RAM:**
    
    - Объём `tmpfs` уменьшается в зависимости от доступной оперативной памяти.
    - Если оперативной памяти не хватает, может начаться свопинг (снижение производительности).
2. **Временность:**
    
    - Данные не сохраняются после остановки контейнера, что делает `tmpfs` неподходящим для постоянного хранения.
3. **Перегрузка памяти:**
    
    - Неправильное использование больших `tmpfs` может истощить доступную RAM и замедлить работу системы.

---

****Пример сценария использования:****

****Сценарий: Тестирование приложения****

При тестировании можно хранить временные данные в `tmpfs`, чтобы ускорить операции и автоматически очищать их после завершения тестов:

```bash
docker run -d --tmpfs /test/data:rw,size=128m test_container
```

Данные в `/test/data` будут храниться только в RAM, а после остановки контейнера удалятся.
