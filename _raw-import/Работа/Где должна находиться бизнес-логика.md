**Где должна находиться бизнес-логика?**

Расположение бизнес-логики зависит от её сложности, переиспользуемости и контекста использования. Вот рекомендации на основе уровней из вашей диаграммы:

---

**1. **На уровне `pages` (Страницы)****

- **Когда использовать:**
    - Если логика специфична для одной страницы и её не нужно переиспользовать.
    - Если логика ограничивается простыми операциями (например, настройка параметров для вызова API или форматирование данных для отображения).
- **Примеры:**
    - Обработка фильтров, переданных пользователем, перед отправкой их в модуль.
    - Определение, какой модуль или компонент должен быть загружен в зависимости от маршрута.
- **Плюсы:**
    - Логика изолирована для конкретной страницы.
    - Упрощается поддержка специфичной функциональности.
- **Минусы:**
    - Нельзя переиспользовать логику на других страницах.

---

**2. **На уровне `modules` (Модули)****

- **Когда использовать:**
    - Если логика сложная и может быть переиспользована в разных местах.
    - Если нужно объединить несколько компонентов, чтобы они взаимодействовали друг с другом через общую логику.
    - Если логика включает в себя работу с API, кэширование, валидацию, бизнес-правила.
- **Примеры:**
    - Логика сортировки, фильтрации, пагинации в "Таблице сервер-сайд".
    - Управление состоянием и валидацией в модуле "Сборка сервер-сайд".
- **Плюсы:**
    - Централизованное управление логикой.
    - Повышение переиспользуемости кода.
- **Минусы:**
    - Модуль может стать слишком сложным, если в нём будет избыточно много логики.

---

**3. **На уровне `components` (Компоненты)****

- **Когда использовать:**
    - Если логика относится только к этому компоненту и никак не влияет на другие части системы.
    - Если это локальная UI-логика (например, валидация ввода, состояние кнопки, отображение модального окна).
- **Примеры:**
    - Показ или скрытие элемента в зависимости от состояния.
    - Локальная обработка событий (например, клик по кнопке).
- **Плюсы:**
    - Простота реализации и локализация.
- **Минусы:**
    - Трудности с переиспользованием, если логика потребуется в другом месте.
    - Риск усложнения компонента, если логика выходит за рамки UI.

---

**4. **На уровне `UI`****

- **Когда использовать:**
    - Если логика касается только стилизации или поведения компонентов UI (например, компоненты Bootstrap).
- **Примеры:**
    - Стилизация элементов, адаптация компонентов к разным темам или экранам.
- **Плюсы:**
    - Локализация логики UI.
- **Минусы:**
    - Полное отсутствие знаний о бизнес-правилах, их нельзя сюда переносить.

---

****Рекомендации:****

- **Бизнес-логика высокой переиспользуемости:** На уровне **`modules`**.
    - Например, модуль "Таблица сервер-сайд" обрабатывает сортировку, фильтры и пагинацию, а также делает запросы к API.
- **Бизнес-логика, специфичная для страницы:** На уровне **`pages`**.
    - Например, логика загрузки данных для одной конкретной страницы.
- **Локальная логика отображения:** На уровне **`components`**.
    - Например, валидация ввода в форме или управление видимостью кнопки.

---

**Пример:**

**На уровне `modules`:**

```javascript
// modules/serverSideTable.js
export function processTableFilters(filters) {
  // Общая бизнес-логика фильтров для таблиц
  return {
    ...filters,
    date: filters.date ? formatDate(filters.date) : null,
  };
}
```

**На уровне `pages`:**

```javascript
import { processTableFilters } from '@/modules/serverSideTable';

const filters = ref({
  search: '',
  date: '',
});

const fetchTableData = async () => {
  const processedFilters = processTableFilters(filters.value);
  tableData.value = await fetchDataFromApi(processedFilters);
};
```

**На уровне `components`:**

```javascript
<template>
  <input v-model="localSearch" @input="onSearch" />
</template>

<script setup>
const localSearch = ref('');
const onSearch = () => {
  emit('update:search', localSearch.value);
};
</script>
```

---

**Вывод:**

Бизнес-логику следует располагать там, где она наиболее эффективно управляется:

- **Модуль** для сложной, многократно используемой логики.
- **Страница** для специфичных сценариев.
- **Компонент** для локальной UI-логики.
