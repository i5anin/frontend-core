**Введение**

Контейнеры в [Docker](./Docker) могут взаимодействовать друг с другом через внутреннюю сеть [Docker](./Docker). Это особенно полезно при построении микросервисной архитектуры, где сервисы общаются между собой напрямую по именам контейнеров. В данном документе описано, как настроить такое взаимодействие, с акцентом на использование MySQL и PHP.

---

**1. Настройка имен контейнеров**

Docker автоматически предоставляет контейнерам возможность взаимодействовать через внутреннюю DNS, используя имена контейнеров. Имя контейнера становится хостом, доступным в сети Docker.

**Пример:**

Если контейнер MySQL называется `db_mysql`, другой контейнер может обращаться к нему как к хосту `db_mysql`.

---

**2. Подключение контейнеров к одной сети**

Для успешного взаимодействия контейнеры должны быть подключены к одной сети Docker. По умолчанию Docker использует сеть `bridge`.

**Проверка сети:**

```bash
docker network inspect bridge
```

**Подключение контейнеров к сети:**

Если контейнеры не находятся в одной сети, подключите их:

```bash
docker network connect bridge php_api
docker network connect bridge db_mysql
```

---

**3. Конфигурация подключения в PHP**

Для взаимодействия с MySQL из PHP используйте имя контейнера MySQL в качестве хоста.

**Пример конфигурации `sql_config.php`:**

```php
<?php
return [
    'server' => getenv('DB_SERVER'), // Имя контейнера MySQL
    'user' => getenv('DB_USER'),
    'pass' => getenv('DB_PASS'),
    'db' => getenv('DB_NAME'),
    'key' => 'SecretKeyPFForum23',
];
```

**Проверка подключения:**

Создайте тестовый скрипт для проверки соединения с базой данных:

```php
<?php
$config = require 'sql_config.php';

$mysqli = new mysqli($config['server'], $config['user'], $config['pass'], $config['db']);

if ($mysqli->connect_error) {
    die('Connection failed: ' . $mysqli->connect_error);
}

echo 'Connected successfully!';
```

Запустите этот скрипт через браузер или команду `curl`.

---

**4. Возможные ошибки и их исправление**

**Ошибка: `No such file or directory`**

Причина: При использовании `localhost` PHP пытается подключиться через Unix-сокет.

**Решение:** Укажите `db_mysql` вместо `localhost`.

**Ошибка: `Connection refused`**

Причина: Контейнеры не находятся в одной сети или MySQL не слушает внешние подключения.

**Решение:**

1. Убедитесь, что контейнеры в одной сети.
2. Проверьте, что MySQL настроен для прослушивания адреса `0.0.0.0`:
    - Измените конфигурацию MySQL (`my.cnf`):
        
        ```ini
        [mysqld]
        bind-address = 0.0.0.0
        ```
        

**Ошибка: `EAI_AGAIN`**

Причина: Проблема с разрешением DNS.

**Решение:**

1. Убедитесь, что контейнеры подключены к правильной сети.
2. Добавьте публичные DNS-серверы в конфигурацию Docker:
    
    ```json
    {
        "dns": ["8.8.8.8", "8.8.4.4"]
    }
    ```
    
3. Перезапустите Docker и контейнеры.

---

**5. Лучшая практика для конфигурации**

1. **Используйте `.env` для хранения конфиденциальных данных:**
    
    ```env
    DB_SERVER=db_mysql
    DB_USER=u1213820_bot
    DB_PASS=fE0xX8qM6nhS3vC9
    DB_NAME=u1213820_elem
    ```
    
2. **Подключите `.env` в PHP:**
    
    ```php
    $config = [
        'server' => getenv('DB_SERVER'),
        'user' => getenv('DB_USER'),
        'pass' => getenv('DB_PASS'),
        'db' => getenv('DB_NAME'),
    ];
    ```
    
3. **Добавьте файлы конфигурации в `.gitignore`:**
    
    ```
    .env
    sql_config.php
    ```
    

---

**Заключение**

Этот протокол помогает настроить безопасное и стабильное взаимодействие между контейнерами Docker через внутреннюю сеть. Убедитесь, что все контейнеры настроены правильно и имеют доступ к необходимым ресурсам. Если возникают ошибки, используйте предоставленные шаги для их устранения.
