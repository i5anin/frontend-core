`docker-compose.yml` — это конфигурационный файл, используемый инструментом **[Docker](./Docker) Compose**, который позволяет легко управлять многоконтейнерными Docker-приложениями. В этом файле описывается, какие контейнеры нужно запустить, как они должны быть связаны между собой, какие порты нужно пробросить, какие переменные окружения нужно установить и т.д.

**Зачем нужен `docker-compose.yml`?**

1. **Управление несколькими контейнерами**: С помощью `docker-compose.yml` можно запускать и управлять несколькими контейнерами, которые составляют приложение (например, API, база данных, кэш, веб-сервер, фронтенд). Вся конфигурация для этих контейнеров описана в одном файле.
    
2. **Упрощение запуска**: Вместо того, чтобы вручную запускать каждый контейнер с нужными флагами, вы можете просто использовать команду `docker-compose up` и Docker Compose автоматически настроит все контейнеры согласно описанию в `docker-compose.yml`.
    
3. **Сетевые настройки и зависимости**: `docker-compose.yml` позволяет настраивать связи между контейнерами (например, указание, что один контейнер зависит от другого), управлять сетями, пробрасывать порты и задавать общие переменные окружения.
    
4. **Автоматизация развёртывания**: Он позволяет легко создавать и тестировать многоконтейнерные приложения, а также использовать его в процессе CI/CD для автоматической сборки и развертывания.
    

**Структура `docker-compose.yml`**

Файл `docker-compose.yml` написан на языке YAML и обычно содержит несколько секций для каждого контейнера (сервиса). Вот основные элементы структуры файла:

1. **version** — версия Docker Compose, которая указывает, какой синтаксис поддерживается.
2. **services** — секция, где описываются все контейнеры (сервисы), которые будут запущены.
3. **volumes** — тома (или хранилища), которые могут быть использованы для хранения данных, чтобы они сохранялись между перезапусками контейнеров.
4. **networks** — сетевые настройки для контейнеров, чтобы они могли взаимодействовать друг с другом.

**Пример `docker-compose.yml`**

Предположим, у вас есть проект, который включает:

- PHP API
- Node.js для Telegram бота
- Vue.js админка
- MySQL база данных

Вот пример конфигурации `docker-compose.yml` для такого проекта:

```yaml
version: '3.7'

services:
  php:
    build:
      context: ./api
      dockerfile: Dockerfile.php
    ports:
      - "8080:80"
    volumes:
      - ./api:/var/www/html
    environment:
      MYSQL_ROOT_PASSWORD: example
      MYSQL_DATABASE: my_database
    depends_on:
      - db

  node:
    build:
      context: ./bot
      dockerfile: Dockerfile.bot
    ports:
      - "3001:3001"
    depends_on:
      - php

  vue:
    build:
      context: ./admin
      dockerfile: Dockerfile.vue
    ports:
      - "80:80"
    depends_on:
      - php

  db:
    image: mysql:5.7
    environment:
      MYSQL_ROOT_PASSWORD: example
      MYSQL_DATABASE: my_database
    ports:
      - "3306:3306"
```

**Объяснение конфигурации:**

1. **`version: '3.7'`**: Указывает, что используется версия 3.7 Docker Compose. Это важно для совместимости синтаксиса.
    
2. **`services:`**: Здесь описаны все контейнеры (сервисы), которые будут запущены в вашем проекте.
    
    - **`php:`**:
        
        - **`build`** — указывает, что для создания образа будет использоваться Dockerfile из папки `/api`.
        - **`ports`** — пробрасывает порт 8080 с контейнера на хост.
        - **`volumes`** — монтирует папку с кодом на хосте в контейнер.
        - **`environment`** — задаёт переменные окружения для базы данных.
        - **`depends_on`** — указывает, что контейнер `php` зависит от контейнера `db` (то есть MySQL должен быть запущен до PHP).
    - **`node:`**:
        
        - Этот контейнер строится из Dockerfile для Telegram бота.
        - Пробрасывает порт 3001.
        - Зависит от контейнера `php` (то есть PHP должен быть доступен перед запуском бота).
    - **`vue:`**:
        
        - Содержит настройки для сборки и запуска Vue.js админки.
        - Пробрасывает порт 80 для доступа к админке.
        - Также зависит от контейнера `php`.
    - **`db:`**:
        
        - Контейнер для MySQL базы данных.
        - Указывает имя базы данных и пароль пользователя.
        - Пробрасывает порт 3306 для доступа к базе данных.

**Как использовать `docker-compose.yml`?**

1. Убедитесь, что у вас есть все нужные `Dockerfile` для каждого компонента (PHP, Node.js, Vue.js).
    
2. В корне проекта создайте файл `docker-compose.yml` и вставьте туда нужную конфигурацию.
    
3. Запустите проект с помощью команды:
    
    ```bash
    docker-compose up --build
    ```
    
    Это создаст и запустит все контейнеры, которые описаны в вашем `docker-compose.yml` файле.
    
4. Для остановки и удаления контейнеров:
    
    ```bash
    docker-compose down
    ```
    

**Преимущества использования Docker Compose:**

- **Простота управления многоконтейнерными приложениями**: Вместо того, чтобы вручную запускать несколько контейнеров с нужными флагами, вы описываете всё в одном файле.
- **Автоматическое связывание контейнеров**: Docker Compose автоматически настраивает взаимодействие между контейнерами, используя общую сеть.
- **Удобство для разработки и тестирования**: Вы можете легко развернуть приложение и его зависимости на своей машине, что упрощает процесс разработки и тестирования.
- **Управление зависимостями**: Docker Compose позволяет явно указать, в каком порядке должны запускаться контейнеры (например, сначала база данных, затем API, затем другие сервисы).

`docker-compose.yml` делает развертывание многоконтейнерных приложений с Docker быстрым и удобным.
