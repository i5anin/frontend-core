[Docker](./Docker) предоставляет несколько уровней изоляции между контейнерами, что делает их независимыми и защищёнными друг от друга. Вот основные уровни изоляции:

---

**1. **Файловая система****

- **Контейнеры имеют изолированную файловую систему.**
    - Каждый контейнер работает в своём собственном файловом пространстве, основанном на образе.
    - По умолчанию изменения файлов в одном контейнере не влияют на другие контейнеры.
    - Разделяемые данные возможны только через **volumes** или **bind mounts**.

---

**2. **Процессы****

- **Контейнеры изолируют процессы.**
    - Процессы внутри контейнера видны только внутри этого контейнера (используется пространство имен **PID namespace**).
    - Контейнеры не могут получить прямой доступ к процессам других контейнеров или хост-системы.

---

**3. **Сеть****

- **Изолированная сеть через bridge.**
    - По умолчанию контейнеры подключаются к виртуальной сети Docker (например, `bridge network`).
    - Контейнеры имеют свои собственные IP-адреса и не видят друг друга напрямую без явного подключения к одной сети.
    - Сетевые взаимодействия возможны только через открытые порты или использование общей сети Docker.

---

**4. **Ресурсы****

- **Ограничение использования ресурсов.**
    - Docker позволяет задавать лимиты для использования:
        - **CPU** (`--cpus`, `--cpu-shares`).
        - **RAM** (`--memory`, `--memory-swap`).
        - **I/O операций** (через `--device-read-bps` и `--device-write-bps`).
    - Это предотвращает ситуацию, когда один контейнер "захватывает" все ресурсы хостовой машины.

---

**5. **Пространство имён (Namespaces)****

Docker использует **Linux Namespaces** для изоляции системных ресурсов:

- **PID namespace**: Изоляция процессов.
- **NET namespace**: Изоляция сетевых интерфейсов.
- **IPC namespace**: Изоляция межпроцессного взаимодействия.
- **MNT namespace**: Изоляция точек монтирования.
- **USER namespace**: Изоляция пользователей, позволяет запускать процессы от привилегированного пользователя в контейнере, но с пониженными правами на хосте.

---

**6. **Контроль доступа через cgroups****

- **Control Groups (cgroups)** ограничивают использование ресурсов.
    - Они предотвращают перерасход ресурсов контейнером, обеспечивая "честное" распределение между всеми работающими контейнерами.

---

**7. **Безопасность и права доступа****

- **AppArmor/SELinux**: Docker может использовать профили AppArmor или SELinux для ограничения действий контейнера.
- **Read-only root filesystem**: Можно задать файловую систему контейнера только для чтения.
- **Capabilities**: Контейнеры запускаются с ограниченным набором возможностей ядра Linux (например, контейнер не имеет root-доступа к ядру).

---

**8. **Docker Networks****

- **Bridge Network** (по умолчанию):
    - Контейнеры внутри одной сети могут взаимодействовать по имени хоста.
    - Контейнеры в разных сетях не могут взаимодействовать.
- **Host Network**:
    - Контейнер использует сеть хоста, что снижает изоляцию.
- **None Network**:
    - Контейнер полностью изолирован от сети.
- **Custom Network**:
    - Позволяет создавать собственные сети с кастомными правилами.

---

**9. **Изоляция на уровне хоста****

Если контейнеры запускаются на одном хосте:

- Они используют общий ядро Linux, что может быть теоретической точкой уязвимости.
- Для дополнительной защиты можно использовать:
    - **Подходы на уровне хоста**: Запускать контейнеры на разных хостах.
    - **VM-бейзированная изоляция**: Например, использование Docker Desktop с WSL2 или Firecracker.

---
