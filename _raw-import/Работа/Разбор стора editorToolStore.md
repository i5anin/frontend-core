## Разбор стора `editorToolStore`

Данный стор отвечает за управление состоянием (данными и логикой) в контексте редактирования инструментов.  

**Содержимое стора:**

**1. Состояние (State):**

* `isLoading`: Флаг загрузки данных.
* `parentCatalog`: Информация о родительском каталоге текущего инструмента (`id`, `label`).
* `dynamicFilters`: Массив доступных динамических фильтров.
* `nameOptions`: Массив опций для выбора имени (не используется в коде).
* `tool`: Объект с данными текущего инструмента.
* `tools`: Массив объектов с данными инструментов.
* `toolsTotalCount`: Общее количество инструментов (для пагинации).
* `filters`: Объект с параметрами фильтрации:
    * `currentPage`: Текущая страница.
    * `itemsPerPage`: Количество элементов на странице.
    * `search`: Строка поиска.
    * `includeNull`: Флаг включения пустых значений (?).
    * `onlyInStock`: Флаг отображения только доступных инструментов (?).
    * `selectedDynamicFilters`: Объект с выбранными динамическими фильтрами.
* `tree`: Массив объектов, представляющих дерево каталогов инструментов.
* `currentItem`: Объект с данными текущего выбранного элемента в дереве.

**2. Действия (Actions):**

* `fetchTree`: Загрузка дерева каталогов.
* `refreshTree`: Обновление дерева каталогов.
* `addFolderToTree`: Добавление папки в дерево.
* `renameFolderInTree`: Переименование папки в дереве.
* `goBackInTree`: Переход на уровень вверх в дереве.
* `findFolderById`: Поиск папки по ID.
* `fetchToolById`: Загрузка данных инструмента по ID.
* `fetchToolsDynamicFilters`: Загрузка доступных динамических фильтров.
* `fetchToolsByFilter`: Загрузка списка инструментов с учётом фильтров.
* `setSearch`: Установка строки поиска.
* `setParentCatalog`: Установка родительского каталога.
* `setDynamicFilters`: Установка доступных динамических фильтров.
* `setSelectedDynamicFilters`: Установка выбранных динамических фильтров.
* `setIsLoading`: Установка флага загрузки.
* `setCurrentPage`: Установка текущей страницы.
* `setFilters`: Установка параметров фильтрации.
* `setTool`: Установка данных текущего инструмента.
* `setItemsPerPage`: Установка количества элементов на странице.
* `setToolsTotalCount`: Установка общего количества инструментов.
* `setTools`: Установка списка инструментов.
* `goToInTree`: Переход к определенному элементу в дереве.
* `selectItemInTree`: Выбор элемента в дереве.

**3. Геттеры (Getters):**

* `getParentCatalog`: Возвращает родительский каталог.
* `getDynamicFilters`: Возвращает доступные динамические фильтры.
* `getFilters`: Возвращает объект с параметрами фильтрации.
* `getTool`: Возвращает данные текущего инструмента (с обработкой свойства `property`).
* `getTools`: Возвращает массив инструментов.
* `getFormattedTools`: Возвращает массив инструментов с преобразованным свойством `property`.
* `getIsLoading`: Возвращает флаг загрузки.
* `getNameOptions`: Возвращает опции для выбора имени (не используется).
* `getToolsTotalCount`: Возвращает общее количество инструментов.
* `getCurrentItem`: Возвращает текущий выбранный элемент в дереве.
* `getTree`: Возвращает дерево каталогов.

**Оптимизация и разделение на файлы:**

1. **Разделение на модули:**

   - Создайте отдельные файлы для:
     - API методов (`toolApi.js`, `treeApi.js`).
     - Модуля дерева каталогов (`tree.js`).
     - Действий (actions) связанных с инструментами (`toolActions.js`) 
     - Действий (actions) связанных с деревом (`treeActions.js`) 
     - Геттеров (getters) (`getters.js`).

   - Это улучшит структуру проекта и читаемость кода.

2. **Использование composables:**

   - Создайте composable для работы с данным стором: [JavaScript](./JavaScript)[Pinia](./Pinia)

     ```javascript
     // store/editorTool.js
     import { defineStore } from 'pinia'
     import * as toolActions from './actions/toolActions' 
     import * as treeActions from './actions/treeActions' 
     import * as getters from './getters' 

     export const useEditorToolStore = defineStore('editorToolStore', {
       state: () => ({
         // ... state
       }),
       actions: {
         ...toolActions, 
         ...treeActions,
       },
       getters
     })

     // composable/useEditorTool.js
     import { useEditorToolStore } from '@/store/editorTool'

     export const useEditorTool = () => {
       const store = useEditorToolStore()
       return {
         ...store
       }
     }
     ```

   - Это упростит использование стора в компонентах.

3. **Оптимизация производительности:**

   - Используйте `computed` свойства для вычисляемых значений, которые зависят от состояния.
   - При необходимости, кешируйте результаты запросов к API.
   - Используйте `watch` для отслеживания изменений в состоянии и выполнения действий только при необходимости.
   - Разделите большой стор на несколько меньших, если это возможно, чтобы избежать 
     перерисовки компонентов при изменении не связанных с ними данных.

4. **Типизация:**

   - Используйте [../../TypeScript/TypeScript](#) для типизации состояния, действий и геттеров.
     Это улучшит читаемость кода, поможет избежать ошибок и облегчит рефакторинг.

**Пример реализации оптимизированного и разделенного стора:**

```
├── store
│   ├── editorTool.js
│   ├── actions
│   │   ├── toolActions.js
│   │   └── treeActions.js
│   └── getters.js
└── composables
    └── useEditorTool.js
```

- Пишите unit-тесты для действий и геттеров стора.
- Документируйте код, используя JSDoc.


Реализация этих рекомендаций сделает ваш код чище, понятнее, проще в поддержке и масштабировании.
