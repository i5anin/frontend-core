****Docker Trust – что это?****

`docker trust` — это команда для управления **Docker Content Trust (DCT)**, механизма подписи образов контейнеров. Она обеспечивает гарантию, что образы не были изменены после публикации и загружаются только из доверенных источников.

---

## **Зачем нужен Docker Trust?**

1. **Гарантирует целостность образа** – никто не сможет подменить контейнер.
2. **Позволяет подписывать образы** – только доверенные разработчики могут загружать обновления.
3. **Защищает от MITM-атак** – предотвращает загрузку вредоносных образов.

---

## **Как включить Docker Trust?**

По умолчанию Docker Trust отключён.  
Чтобы включить **Docker Content Trust (DCT)**, нужно задать переменную:

```sh
export DOCKER_CONTENT_TRUST=1
```

Теперь при `docker pull` или `docker push` Docker будет требовать подпись образа.

---

## **Основные команды `docker trust`**

|Команда|Описание|
|---|---|
|`docker trust inspect <image>`|Проверяет подпись образа|
|`docker trust sign <image>`|Подписывает образ|
|`docker trust revoke <image>`|Отзывает подпись у образа|

📌 **Пример проверки подписи:**

```sh
docker trust inspect nginx
```

Если образ подписан, будет показана информация о подписи.

---

## **Как подписать образ?**

1️⃣ **Создать пару ключей (если нет)**

```sh
docker trust key generate mykey
```

2️⃣ **Добавить доверенные ключи в реестр**

```sh
docker trust signer add --key mykey.pub myuser <repo>
```

3️⃣ **Подписать образ**

```sh
docker trust sign myrepo/myimage:latest
```

---

## **Когда `docker trust` бесполезен?**

- Если **образ хранится в частном реестре** без поддержки подписи.
- Если **используется Podman**, так как Podman имеет альтернативные механизмы безопасности.
- Если **контейнеры уже запускаются в изолированной среде**, например, в Kubernetes с Pod Security Policies.

---

## **Вывод**

✅ `docker trust` полезен, если ты работаешь с публичными реестрами и хочешь защититься от подмены образов.  
✅ Если твой реестр поддерживает подписи, стоит включить `DOCKER_CONTENT_TRUST=1`.  
❌ **Не нужен**, если ты работаешь только с приватными образами или уже используешь Podman/Kubernetes.
