****Дополнительные сущности в `docker-compose.yml`****

Помимо `environment`, `depends_on`, `networks` и `volumes`, в `docker-compose.yml` могут быть и другие параметры:

---

****5. `ports` (Порты)****

📌 **Пробрасывает порты контейнера на хост-систему.**  
Используется для обеспечения внешнего доступа к сервисам внутри контейнера.

**Пример:**

```yaml
ports:
  - "8080:80"  # Пробрасываем порт 80 контейнера на 8080 хоста
```

---

****6. `restart` (Перезапуск контейнера)****

📌 **Определяет политику перезапуска контейнера при его остановке.**

**Варианты значений:**

- `no` – контейнер не перезапускается (по умолчанию).
- `always` – контейнер всегда перезапускается.
- `on-failure` – перезапуск только при завершении с ошибкой.
- `unless-stopped` – перезапускается, если его не остановили вручную.

**Пример:**

```yaml
restart: always
```

---

****7. `build` (Сборка образа)****

📌 **Определяет, откуда собирать образ для контейнера.**

**Пример:**

```yaml
build:
  context: ./api
  dockerfile: Dockerfile
```

---

****8. `command` (Команда запуска)****

📌 **Заменяет команду, указанную в `CMD` внутри `Dockerfile`.**  
Полезно для переопределения стандартного поведения контейнера.

**Пример:**

```yaml
command: ["npm", "start"]
```

---

****9. `entrypoint` (Точка входа)****

📌 **Заменяет `ENTRYPOINT` в `Dockerfile`.**  
Используется, если нужно выполнить определённый скрипт перед основной командой.

**Пример:**

```yaml
entrypoint: ["/app/start.sh"]
```

---

****10. `healthcheck` (Проверка работоспособности)****

📌 **Позволяет [Docker](./Docker) проверять состояние контейнера.**  
Если контейнер не проходит проверку, он считается "unhealthy" и может быть перезапущен.

**Пример:**

```yaml
healthcheck:
  test: ["CMD", "curl", "-f", "http://localhost"]
  interval: 30s
  timeout: 10s
  retries: 3
```

---

****11. `extra_hosts` (Дополнительные хосты)****

📌 **Добавляет записи в `/etc/hosts` контейнера.**  
Позволяет контейнерам использовать кастомные DNS-имена.

**Пример:**

```yaml
extra_hosts:
  - "api.local:192.168.1.100"
```

---

****12. `ulimits` (Ограничения ресурсов)****

📌 **Задаёт лимиты на использование ресурсов в контейнере.**  
Например, можно ограничить максимальное количество открытых файлов.

**Пример:**

```yaml
ulimits:
  nofile:
    soft: 65536
    hard: 65536
```

---

****13. `logging` (Логирование)****

📌 **Определяет драйвер логирования для контейнера.**  
Можно, например, отправлять логи в `json-file` или `syslog`.

**Пример:**

```yaml
logging:
  driver: "json-file"
  options:
    max-size: "10m"
    max-file: "3"
```

---

****14. `secrets` (Секреты)****

📌 **Позволяет хранить чувствительные данные (пароли, API-ключи) безопасно.**  
Используется в Swarm-моде [Docker](./Docker).

**Пример:**

```yaml
secrets:
  my_secret:
    file: ./secrets/db_password.txt
```

---

****15. `configs` (Конфигурационные файлы)****

📌 **Позволяет управлять конфигурационными файлами внутри контейнера.**

**Пример:**

```yaml
configs:
  app_config:
    file: ./config/app.json
```

---

****Категоризация сущностей****

|Категория|Сущности|
|---|---|
|**Сетевые настройки**|`networks`, `ports`, `extra_hosts`|
|**Перезапуск и управление жизненным циклом**|`restart`, `depends_on`, `healthcheck`|
|**Ресурсы и ограничения**|`ulimits`|
|**Переменные окружения и настройки**|`environment`, `secrets`, `configs`|
|**Запуск команд**|`command`, `entrypoint`|
|**Логирование**|`logging`|
|**Сборка образа и тома**|`build`, `volumes`|

---

Эти сущности помогают более **гибко и безопасно** управлять контейнерами в `docker-compose.yml`. 🚀
