****Что такое Volume в [Docker](./Docker)?****

[Docker](./Docker) Volumes — это способ хранения данных, которые нужны контейнерам, вне самого контейнера. Они используются для обеспечения сохранности данных и их разделения между контейнерами.

---

****Глобальный смысл (логический):****

1. **Сохранение данных вне контейнера:**
    
    - Контейнеры в Docker изолированы, а их файловая система временная. Если контейнер удаляется, данные, хранящиеся внутри него, исчезают. Volumes позволяют хранить данные вне контейнера и сохранять их даже после удаления контейнера.
2. **Совместное использование данных между контейнерами:**
    
    - Несколько контейнеров могут использовать один и тот же volume для доступа к общим данным.
3. **Упрощение работы с данными:**
    
    - Volumes делают перенос данных между контейнерами и хостом проще, особенно при работе с приложениями, которым нужно хранить или читать большие объёмы информации.

---

****Физический смысл:****

1. **Хранилище на хосте:**
    
    - Volumes хранятся на хосте (в папке Docker, например, `/var/lib/docker/volumes` на Linux или в WSL для Docker Desktop).
    - Это означает, что данные находятся вне контейнера и остаются доступными, даже если контейнер удаляется.
2. **Механизм монтирования:**
    
    - Volume монтируется в контейнер как папка. Контейнер видит данные так, как будто они находятся внутри его файловой системы.

---

****Что можно делать с помощью Volume?****

**1. **Создание Volume****

Создание отдельного volume:

```bash
docker volume create my_volume
```

**2. **Использование Volume в контейнере****

При запуске контейнера volume монтируется в определённую папку внутри контейнера:

```bash
docker run -d -v my_volume:/app/data --name my_container nginx
```

- `my_volume` — имя volume.
- `/app/data` — папка внутри контейнера, где volume будет виден.

**3. **Общие данные для нескольких контейнеров****

Несколько контейнеров могут работать с одним volume:

```bash
docker run -d -v my_volume:/app/data --name container1 nginx
docker run -d -v my_volume:/app/data --name container2 nginx
```

- Оба контейнера смогут читать и писать данные в `/app/data`.

**4. **Просмотр списка Volume****

Список всех созданных volume:

```bash
docker volume ls
```

**5. **Удаление Volume****

Удаление неиспользуемого volume:

```bash
docker volume rm my_volume
```

Удаление всех неиспользуемых volume:

```bash
docker volume prune
```

**6. **Подключение локальной директории вместо Volume****

Если нужно подключить конкретную папку на хосте вместо Volume:

```bash
docker run -d -v /path/on/host:/app/data --name my_container nginx
```

- Вместо volume используется путь `/path/on/host`.

**7. **Копирование данных в Volume****

Для инициализации volume данными:

- Сначала скопируй данные в папку внутри контейнера.
- Или используй `docker cp` для копирования данных между хостом и контейнером:
    
    ```bash
    docker cp ./data my_container:/app/data
    ```
    

---

****Когда использовать Volume?****

1. **Сохранение данных базы данных**:
    
    - Храни данные от MySQL, PostgreSQL, MongoDB в volume, чтобы не потерять их после удаления контейнера:
        
        ```bash
        docker run -d -v my_db_volume:/var/lib/mysql mysql
        ```
        
2. **Общие файлы между контейнерами**:
    
    - Например, при создании системы, где фронтенд и бэкенд используют одни и те же данные.
3. **Логирование**:
    
    - Сохрани логи контейнера на volume для последующего анализа.
4. **Обновление данных приложения**:
    
    - Например, ты можешь менять файлы приложения на хосте, и контейнер сразу будет видеть изменения.

---

****Преимущества Volume****

- Данные живут независимо от контейнеров.
- Легко использовать общие данные между несколькими контейнерами.
- Упрощённая организация работы с данными.

---

****Пример: Docker Compose и Volumes****

В `docker-compose.yml`:

```yaml
services:
  app:
    image: my_app
    volumes:
      - my_volume:/app/data

volumes:
  my_volume:
```

После запуска:

```bash
docker-compose up
```

Volume `my_volume` автоматически создаётся и подключается к `/app/data`.
