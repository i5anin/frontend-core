Изоляция операционной системы (OS) от программ может быть выполнена разными способами в зависимости от целей: безопасность, стабильность, отказоустойчивость или тестирование. Рассмотрим основные методы.

---

**1️⃣ **Контейнеризация (Docker, Podman, LXC)****

**✅ Лучший вариант для изоляции приложений, но не всей ОС.**  
Контейнеры работают в одном ядре, но имеют отдельные процессы, файловую систему и сетевые настройки.

- **Docker** — упрощает развертывание и изоляцию приложений.
- **Podman** — без демон-процесса (в отличие от Docker).
- **LXC/LXD** — ближе к виртуализации, более легковесные контейнеры.

📌 **Пример запуска контейнера с Ubuntu без доступа к основной системе:**

```sh
docker run -it --rm ubuntu bash
```

Этот контейнер создаст отдельное пространство процессов, сетевых интерфейсов и файловую систему.

---

**2️⃣ **Виртуализация (KVM, VirtualBox, VMware, Hyper-V)****

**✅ Полностью изолирует гостевую ОС от основной.**  
Подходит, если требуется полная независимость приложений от хостовой системы.

- **KVM** (Kernel-based Virtual Machine) — встроен в Linux, быстрый.
- **VirtualBox** — удобен для тестирования.
- **VMware/Hyper-V** — корпоративные решения.

📌 **Пример создания виртуальной машины с KVM/QEMU:**

```sh
qemu-system-x86_64 -m 2048 -hda disk.img -net nic -net user
```

Эта команда запускает виртуальную машину с 2 ГБ RAM и диском `disk.img`.

---

**3️⃣ **Песочницы (AppArmor, SELinux, Firejail)****

**✅ Изоляция процессов внутри ОС, без виртуализации.**  
Подходит для запуска опасных программ (браузеры, сторонний софт).

- **Firejail** — ограничивает доступ приложения к системе.
- **AppArmor/SELinux** — политики контроля доступа для процессов.

📌 **Пример запуска браузера в Firejail:**

```sh
firejail --net=none firefox
```

Запускает Firefox без сетевого доступа.

---

**4️⃣ **Изоляция через chroot (старый способ)****

**✅ Работает, но устарел, так как контейнеры и виртуалки удобнее.**  
Создает "фейковую" корневую файловую систему.

📌 **Пример chroot в Ubuntu:**

```sh
mkdir /opt/chroot
debootstrap --arch=amd64 focal /opt/chroot http://archive.ubuntu.com/ubuntu
chroot /opt/chroot /bin/bash
```

Теперь запущенные программы видят `/opt/chroot` как корень.

---

**5️⃣ **Изоляция через ограничения ядра (Cgroups, Namespaces)****

**✅ Гибкий, но сложный метод (используется в Docker и Kubernetes).**

- **Cgroups** — ограничивает ресурсы (CPU, RAM, I/O).
- **Namespaces** — изолирует процессы, сеть, файловую систему.

📌 **Пример ограничения процесса 100 МБ RAM:**

```sh
cgcreate -g memory:/limited
echo 100M > /sys/fs/cgroup/memory/limited/memory.limit_in_bytes
cgexec -g memory:/limited some_program
```

---

**🔥 **Что выбрать?****

|Метод|Изоляция|Ресурсы|Использование|
|---|---|---|---|
|**Docker**|Средняя|Легкие|Разработка, деплой|
|**LXC/LXD**|Высокая|Легкие|Изолированные сервисы|
|**VirtualBox/KVM**|Полная|Тяжелые|Полноценная изоляция ОС|
|**Firejail**|Средняя|Легкие|Безопасность процессов|
|**AppArmor/SELinux**|Средняя|Легкие|Защита ядра|
|**Chroot**|Низкая|Средние|Устаревший вариант|
|**Cgroups**|Средняя|Средние|Ограничение ресурсов|

✅ **Если нужна полная изоляция** → Виртуализация (KVM, VirtualBox).  
✅ **Если нужна легковесная изоляция** → Контейнеры (Docker, LXC).  
✅ **Если нужна защита в пределах ОС** → Firejail, AppArmor, SELinux.
