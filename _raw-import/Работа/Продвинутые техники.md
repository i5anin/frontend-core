# 🛠 Продвинутые техники

> [← к оглавлению серии](./📌 Введение в промпт-инжиниринг)

Семь техник, которые отличают «обычного юзера» от того, кто **выжимает из Claude максимум**. Каждая решает свою задачу — не нужно применять все сразу.

## 1. Chain of Thought (CoT) — «думай по шагам»

Идея: попроси модель **сначала рассуждать, потом отвечать**. Качество ответа на сложных задачах вырастает заметно.

```plain
✅ Сначала проанализируй код пошагово:
   - что делает каждая функция
   - где могут быть узкие места
Только после анализа дай итоговый список рекомендаций.
```

Магические фразы:
- «Подумай шаг за шагом»
- «Сначала рассуждай вслух, потом отвечай»
- «Перед ответом разбери задачу на части»

> [!warning] Когда CoT не нужен
> Для простых задач («переведи слово», «дай 3 примера») CoT только **раздувает ответ**. Используй только когда задача требует анализа: ревью кода, дебаг, архитектурное решение, сравнение вариантов.


## 2. Few-Shot prompting — «учи примерами»

Когда задача нестандартная или у тебя свой формат — покажи 2–4 примера. Модель подхватит паттерн.

```plain
Преобразуй название коммита в conventional commit.

Примеры:
"добавил кнопку логина" → "feat(auth): add login button"
"поправил баг с пустым корзиной" → "fix(cart): handle empty state"
"переименовал переменные" → "refactor: rename variables"

Теперь обработай: "сломал сборку при импорте"
```

> [!tip]
> Few-Shot **сильнее любых инструкций**. Если ты 10 раз объяснил формат и не получилось — дай 3 примера, и модель поймёт мгновенно.


## 3. XML-теги для структуры

Claude обучен на XML-разметке и реагирует на неё **лучше, чем на markdown** или произвольные разделители.

```xml
<role>Senior code-reviewer</role>

<task>
Найди потенциальные баги в коде ниже.
</task>

<rules>
- Фокус на null/undefined
- Игнорируй стиль (его проверит линтер)
- Если бага нет — так и скажи
</rules>

<code>
function calculateTotal(items) {
  return items.reduce((sum, item) => sum + item.price, 0);
}
</code>
```

Любые осмысленные теги работают: `<task>`, `<context>`, `<example>`, `<format>`, `<code>`, `<data>`, `<rules>`. Главное — закрывать (`</task>`).

## 4. Prefilling — «начни ответ за модель»

Работает чуть иначе в чате: можно попросить **продолжить с конкретной фразы** — это «заякорит» формат.

```plain
Дай ответ, начиная строго со строки:

"```json
{
  "errors": [
```

Дальше — массив объектов вида { line, message, severity }.
```

Особенно полезно для JSON, кода, структурированных списков — модель не будет вставлять вступительный «бла-бла».

## 5. Projects и кастомные инструкции

Это убойная штука в claude.ai, которую большинство не использует.

> [!important] Что это
> **Projects** — твоё рабочее пространство с **постоянным system prompt** и общими файлами. Всё, что ты туда положишь, видно во всех чатах внутри проекта.


Что класть в **system instructions** проекта:
```plain
Я — Vue 3 разработчик. Уровень — middle.
Стек: Vue 3 Composition API, Pinia, Vite, TypeScript.
Не объясняй базовый синтаксис JS/Vue, я его знаю.
Код всегда давай на TS, если явно не сказано иначе.
Отвечай по делу, без длинных вступлений.
Если что-то не очевидно — сначала уточни, потом отвечай.
```

После этого **каждый** чат в проекте уже знает, кто ты, и не нужно повторять контекст. Огромная экономия.

Файлы в проект: документация твоей кодовой базы, стайл-гайд команды, типы из core-проекта. Claude будет «помнить» их во всех чатах.

## 6. Артефакты — используй явно

Артефакты — отдельное окно справа с кодом / документом / SVG. Они **редактируемые** и видны целиком.

| Когда просить артефакт | Когда НЕ нужен |
|---|---|
| Код длиннее 20 строк | Короткий снипет |
| Документ, который пойдёт в работу | Объяснение концепции |
| HTML/SVG/Mermaid для просмотра | Дискуссия и анализ |
| То, что будешь итеративно править | Список идей |

```plain
✅ Перепиши компонент в Composition API.
   Положи код в артефакт, чтобы я мог копировать целиком.
```

## 7. Вложения (файлы, PDF, картинки)

В чат можно прикреплять файлы. Несколько неочевидных моментов:

- **Картинки**: Claude хорошо читает скриншоты кода, диаграммы, графики, UI-моки. Можно дать макет и попросить сверстать.
- **PDF**: можно кидать целиком, до сотен страниц. Спрашивать в духе «найди всё про X», «суммаризируй главу 3».
- **Несколько файлов**: можно положить 5 файлов проекта и попросить «найди баг в связке между ними».
- **Большие файлы**: если файл огромный и большая часть нерелевантна — сначала **вырежи нужный кусок**, иначе модель отвлекается.

## Когда какую технику применять

| Задача | Главная техника |
|---|---|
| Длинный сложный анализ | **CoT** (думай по шагам) |
| Свой формат вывода / нестандартная задача | **Few-Shot** (2–4 примера) |
| Многокомпонентный промпт с данными | **XML-теги** |
| Нужен строгий формат (JSON, код) | **Prefilling** |
| Повторяющиеся задачи в одной теме | **Project** + system prompt |
| Большой код / документ на выходе | **Артефакт** |
| Работа с готовыми данными | **Вложения** |

> [!tip] Не нужно применять всё сразу
> Хорошие промпты обычно используют **1–2** техники, а не 7. Подбирай под задачу.
