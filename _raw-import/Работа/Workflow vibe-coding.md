# Workflow vibe-coding — как реально работать с AI-агентом

> Не «попросил → получил мусор → переделал руками». А **система** для качественного результата.

> [!tip] Принцип
> **AI — не магия.** Это **усилитель** твоих способностей. Хороший промпт + хороший ревью = хороший код.

---

## Воронка задач

```
🌊 ВСЕ задачи
   ↓
🎯 Разделить: «ясная» vs «исследовательская»
   ↓
   ├─ Ясная → дать агенту целиком      (90% работы)
   └─ Исследовательская → шаги вместе  (10% работы)
   ↓
✅ Ревью результата
   ↓
🚀 Коммит
```

---

## Типы задач

**1. Боевые (даёшь агенту полностью)**

- Фичи с чёткими требованиями
- Рефакторинг по понятному паттерну
- Миграции (Vue 2 → Vue 3, JS → TS)
- Написание тестов по существующему коду
- Документация
- Багфиксы с воспроизведением
- CSS / стайлинг по дизайну
- Конфиги, скрипты, CI/CD

> [!success] Это 80% всей разработки

**2. Исследовательские (вместе с агентом)**

- Архитектурные решения
- Выбор подхода / технологии
- Сложные баги без воспроизведения
- Оптимизация производительности
- Безопасность / угрозы
- Бизнес-логика без чётких требований

> [!warning] Здесь важен **диалог**

**3. Не давать агенту**

- Кросс-системные интеграции с несколькими микросервисами
- Критичные платёжные операции без двойной проверки
- Удаление продакшен-данных
- Изменение DNS / прод-конфигов
- Запросы где **ты сам не понимаешь** что должно получиться

## Шаблон промпта

```
КОНТЕКСТ
- Что за проект, стек, цель
- Релевантные файлы

ЗАДАЧА
- Что сделать
- Критерии готовности

ОГРАНИЧЕНИЯ
- Чего НЕ делать (не менять X, не трогать Y)
- Стиль кода
- Соглашения проекта

ОЖИДАНИЕ
- Что должно получиться на выходе
- Как проверить
```

**Пример**

```
КОНТЕКСТ
Vue 3.5 + TS + Pinia. Фронтенд CRM.
Файлы: src/features/auth/.

ЗАДАЧА
Добавить refresh-token логику в pinia auth-store.
При 401 — попытка refresh. Если refresh упал — logout.

ОГРАНИЧЕНИЯ
- Не трогать существующий router guard
- Использовать interceptor axios который уже есть
- TS strict mode

ОЖИДАНИЕ
- Обновлённый src/features/auth/api/refresh.ts
- Тесты в spec.ts (vitest)
- README обновить
```

## 4 режима использования

**Режим A: «Я смотрю, агент пишет»**

- Cursor с Tab-автокомплитом
- Claude Code в pair-mode
- Ты редактируешь, AI догоняет

**Когда:** обычная разработка, мелкие задачи, обучение.

**Режим B: «Я даю задачу, агент делает»**

- Claude Code agent
- Cursor Composer
- Aider

**Когда:** понятные фичи, рефакторинг.

**Режим C: «Я даю задачу — ухожу — приходит готовое»**

- Devin
- Cursor Background agents
- Claude Code Workflow

**Когда:** рутина, тесты, миграции.

**Режим D: «От идеи до приложения»**

- Bolt.new / Lovable
- v0 (для UI)
- Replit Agent

**Когда:** прототипы, MVP, тестирование идей.

## Чек-лист «хороший вибе-сеанс»

> [!tip] Перед стартом
> - [ ] Чёткая задача в одном предложении
> - [ ] Знаю что в репо релевантно
> - [ ] Знаю критерии готовности
> - [ ] Понимаю в общих чертах, как должно работать

> [!warning] Во время
> - [ ] Не молчу, если агент ушёл не туда — сразу останавливаю
> - [ ] Прошу объяснить решение, если не понимаю
> - [ ] Не позволяю «расползтись» за рамки задачи

> [!danger] После
> - [ ] Прочитал **каждый** изменённый файл (хотя бы по диагонали)
> - [ ] Запустил тесты
> - [ ] Проверил визуально в браузере
> - [ ] Понимаю, что закоммитил

## Антипаттерны

**1. «Сделай мне всё»**

```
❌ "Сделай мне CRM"
✅ "Добавь модуль клиентов с CRUD: список, форма, БД supabase.
    Файлы: src/features/clients/"
```

**2. Слепое доверие**

> «Я не смотрел, но раз AI написал — должно работать»

**Никогда.** AI делает ошибки. **Ревью обязательно.**

**3. Бесконечный пинг-понг**

Если 5 итераций — а результата нет → **проблема в задаче**, не в агенте. Переформулируй.

**4. Игнор контекста**

```
❌ "Напиши функцию валидации формы"
✅ "Напиши функцию валидации формы. У нас Vee-Validate + Yup,
    схему положи рядом с компонентом, ошибки в i18n."
```
