****Что такое [Docker](./Docker) Context?****

`docker context` — это механизм в Docker, позволяющий переключаться между разными конфигурациями Docker Engine. Например, вы можете управлять локальными контейнерами, удалёнными серверами Docker, облачными кластерами (например, AWS ECS) и другими окружениями, не меняя глобальные настройки Docker.

---

****Для чего нужен Docker Context?****

1. **Работа с удалёнными Docker-хостами**:
    
    - Если у вас есть удалённый сервер с установленным Docker, `docker context` позволяет переключаться на него, не указывая вручную параметры подключения.
2. **Управление несколькими окружениями**:
    
    - Например, локальный Docker для разработки и удалённый для тестирования или продакшена.
3. **Интеграция с облаком**:
    
    - Контексты используются для работы с облачными провайдерами, такими как AWS ECS, Azure ACI и другими.

---

****Основные команды Docker Context****

**1. **Список доступных контекстов****

```bash
docker context ls
```

Пример вывода:

```
NAME                DESCRIPTION                               DOCKER ENDPOINT
default *           Current DOCKER_HOST based configuration  unix:///var/run/docker.sock
remote-server       Docker on remote host                    ssh://user@192.168.1.100
```

- `default` — контекст по умолчанию (ваш локальный Docker).
- `remote-server` — пример удалённого контекста.

**2. **Переключение между контекстами****

```bash
docker context use remote-server
```

После этого все команды Docker (`docker ps`, `docker images` и т.д.) будут выполняться на удалённом сервере, указанном в контексте `remote-server`.

Чтобы вернуться на локальный Docker:

```bash
docker context use default
```

**3. **Создание нового контекста****

Например, для удалённого сервера с использованием SSH:

```bash
docker context create remote-server --docker "host=ssh://user@192.168.1.100"
```

- `remote-server` — имя нового контекста.
- `host=ssh://user@192.168.1.100` — SSH-подключение к удалённому серверу.

**4. **Удаление контекста****

Если контекст больше не нужен:

```bash
docker context rm remote-server
```

**5. **Просмотр текущего контекста****

Чтобы узнать, какой контекст используется в данный момент:

```bash
docker context show
```

Пример:

```
default
```

---

****Пример использования****

**Управление удалённым сервером:**

1. Создаём контекст для сервера:
    
    ```bash
    docker context create prod-server --docker "host=ssh://user@your-remote-host"
    ```
    
2. Переключаемся на него:
    
    ```bash
    docker context use prod-server
    ```
    
3. Выполняем команды, например:
    
    ```bash
    docker ps
    ```
    
    Результат будет получен с удалённого сервера.
    
4. Возвращаемся к локальному Docker:
    
    ```bash
    docker context use default
    ```
    

---

****Примечания****

- Контексты хранятся локально, в настройках Docker (обычно в `~/.docker/contexts`).
- Они позволяют избежать необходимости передавать параметры `DOCKER_HOST` вручную для каждого подключения.
- Для удалённых контекстов может потребоваться SSH-доступ и настройка ключей.
