# Оптимизация Dockerfile и docker-compose

## Основные принципы оптимизации Dockerfile

**1. Легкие образы (`slim`)**

Используйте легкие версии базовых образов, такие как `python:3.11.9-slim` или `node:alpine`, чтобы минимизировать размер итогового образа.

**2. Установка зависимостей (`RUN`) перед копированием файлов**

Разделяйте копирование файлов:

- Сначала копируйте файлы зависимостей (например, `requirements.txt` или `package.json`), так как они редко меняются.
- Затем копируйте остальные файлы проекта.

Этот подход позволяет использовать кэширование [Docker](./Docker) и ускоряет сборку образов.

Пример для Python:

```Dockerfile
FROM python:3.11.9-slim

# Сначала копируем только файлы зависимостей
COPY requirements.txt requirements.txt
RUN pip install -r requirements.txt

# Затем копируем весь проект
COPY . .

CMD [ "python", "main.py" ]
```

Пример для Node.js:

```Dockerfile
FROM node:alpine as build

# Копируем только файлы зависимостей
COPY package.json package.json
RUN npm install

# Затем копируем весь проект
COPY . .
RUN npm run build

FROM nginx:stable-alpine

# Копируем собранные файлы фронтенда в Nginx
COPY --from=build /dist /usr/share/nginx/html
COPY --from=build nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 3000
CMD [ "nginx", "-g", "daemon off;" ]
```

## Оптимизация docker-compose.yml

```yaml
networks: # Определение всех сетей
  dev: # Создание пользовательской сети для связи между сервисами

services: # Определение всех сервисов
  nginx: # Сервис веб-сервера Nginx
    image: nginx:stable-alpine # Легкий образ Nginx
    ports: # Определение проброса портов
      - "80:80" # Проброс порта 80 для HTTP
      - "443:443" # Проброс порта 443 для HTTPS
    volumes: # Определение подключаемых томов
      - './nginx.conf:/etc/nginx/nginx.conf' # Локальный файл конфигурации для Nginx
      - '/etc/letsencrypt:/etc/letsencrypt' # Сертификаты Let's Encrypt для SSL
    depends_on: # Определение зависимостей сервиса
      - backend # Зависимость от сервиса backend
      - frontend # Зависимость от сервиса frontend
    networks: # Подключение сервиса к сети
      - dev # Подключение к пользовательской сети "dev"

  backend: # Сервис для серверной части приложения
    build: # Определение параметров сборки Docker-образа
      context: ./backend # Путь к исходным файлам для сборки backend
    networks: # Подключение сервиса к сети
      - dev # Подключение к пользовательской сети "dev" для взаимодействия с другими сервисами

  frontend: # Сервис для клиентской части приложения
    build: # Определение параметров сборки Docker-образа
      context: ./frontend # Путь к исходным файлам для сборки frontend
    networks: # Подключение сервиса к сети
      - dev # Подключение к пользовательской сети "dev" для взаимодействия с другими сервисами
```

**Пояснения:**

- **`networks`**: Определяет пользовательскую сеть, чтобы сервисы могли взаимодействовать друг с другом через внутренние DNS. Например, `backend` и `frontend` могут обращаться друг к другу по именам.
- **`services`**: Содержит описание всех сервисов (например, `nginx`, `backend`, `frontend`), которые запускаются в Docker Compose.
- **`image`**: Указывает базовый образ для запуска сервиса (например, `nginx:stable-alpine`).
- **`build`**: Определяет параметры сборки Docker-образа, включая путь к исходникам.
- **`ports`**: Настраивает проброс портов между хостом и контейнером.
- **`volumes`**: Подключает файлы и директории с хоста внутрь контейнера.
- **`depends_on`**: Определяет порядок запуска сервисов.

## Резюме

1. **Легкие образы:** Используйте `slim` или `alpine` версии базовых образов.
2. **Кэширование:** Разделяйте копирование файлов зависимостей и остальных файлов проекта.
3. **Оптимизация docker-compose:** Четко указывайте зависимости между сервисами и используйте пользовательские сети для связи.
