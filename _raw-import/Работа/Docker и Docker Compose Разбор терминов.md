**1. **[Docker](./Docker)****

[Docker](./Docker) — это платформа, которая позволяет разрабатывать, тестировать и запускать приложения в изолированных контейнерах. Контейнеры содержат всё необходимое для работы приложения: код, зависимости, системные библиотеки. Docker обеспечивает одинаковую работу приложения на любом устройстве, где установлен Docker.

---

**2. **Docker Compose****

Docker Compose — это инструмент для работы с несколькими контейнерами, которые формируют единую систему. С помощью файла `docker-compose.yml` вы описываете, какие контейнеры и как они взаимодействуют. Например, вы можете задать базу данных, сервер, боты, которые работают вместе.

**tg_bot** в контексте `docker-compose` — это, вероятно, имя службы (service) в `docker-compose.yml`, которая запускает ваш Telegram-бот.

---

**3. **Dev Containers****

Dev Containers (контейнеры для разработки) — это концепция, используемая в основном в редакторах, таких как VS Code. Она позволяет разрабатывать приложение непосредственно внутри контейнера, где уже установлены все необходимые зависимости. Это помогает избежать проблем с локальной настройкой окружения и конфигурацией.

---

**4. **Containers (Контейнеры)****

Контейнеры — это изолированные экземпляры приложений, которые работают на основе образов Docker. В контейнере находится:

- Само приложение (например, Telegram-бот).
- Все зависимости.
- Настройки, описанные в `docker-compose.yml` или в командной строке при запуске.

Каждый контейнер:

- Изолирован от других.
- Имеет своё собственное файловое пространство и ресурсы.

---

**5. **Images (Образы)****

Образы — это шаблоны, на основе которых запускаются контейнеры. Они состоят из:

- Базовой операционной системы (например, Alpine или Ubuntu).
- Установленных приложений и библиотек (например, Python или Node.js).

**Пример:**

- Вы скачиваете образ `python:3.9`.
- Запускаете на его основе контейнер для вашего Telegram-бота.

---

**6. **Networks (Сети)****

Сети — это виртуальные подсети, через которые контейнеры могут взаимодействовать друг с другом. Docker автоматически создаёт сеть `bridge`, но вы можете настроить свои сети.

Типы сетей:

- **Bridge** (по умолчанию): Используется для связи контейнеров на одном хосте.
- **Host**: Использует сетевой стек хоста (без изоляции).
- **Overlay**: Для связи между контейнерами на разных хостах.

---

**7. **Volumes (Томахранилища)****

Тома — это способ сохранять данные контейнера за пределами его файловой системы. Данные, сохранённые в томе, не удаляются при остановке или удалении контейнера. Используется для:

- Хранения данных баз данных (например, MySQL).
- Логов и файлов конфигурации.
- Совместного доступа нескольких контейнеров к одним данным.

**Пример:** Если ваш Telegram-бот пишет логи в файл, лучше использовать том, чтобы они не пропадали после остановки контейнера.
