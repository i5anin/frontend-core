# Интервью и найм

## Типы технических интервью

### 1. Скрининг (30-45 мин)
```
Цель: проверить базовые знания и фит с вакансией

Формат:
- Вопросы о прошлом опыте
- 1-2 технических вопроса
- Вопросы о стеке (Vue/React, TypeScript, CSS)

Что оценивают:
- Адекватность ожиданий (зарплата, формат работы)
- Базовый технический уровень
- Коммуникация
```

### 2. Техническое интервью (1-2 часа)
```
Лайв-кодинг:
- Задача на алгоритмы / структуры данных
- Реализация компонента
- Решение реальной проблемы

Архитектурное задание:
- Спроектировать систему
- Объяснить решения

Вопросы по теории:
- Event Loop, Prototype Chain
- CSS specificity, Flexbox, Grid
- Vue reactivity, жизненный цикл
```

### 3. Системный дизайн (Senior)
```
Задача: "Спроектируй Instagram-подобный сервис"

Ожидаемый подход:
1. Уточнить требования (DAU, функции)
2. Определить ключевые компоненты
3. Обсудить хранение данных
4. Продумать масштабирование
5. Обозначить риски и компромиссы
```

## Подготовка к интервью

### Структура ответа STAR

```
Situation — Опишите контекст
Task      — Какова была задача
Action    — Что вы сделали
Result    — Каков был результат (с числами)

Пример:
"В прошлом проекте (S) нужно было оптимизировать загрузку (T).
Я провёл профилирование, нашёл N+1 запросы и внедрил кэширование (A).
В результате время загрузки снизилось с 4с до 800мс (R)"
```

### Ответы на поведенческие вопросы

```
"Расскажите о конфликте в команде"
→ STAR: контекст → ваши действия → позитивный исход

"Ваша самая большая ошибка"
→ Конкретный пример → что узнали → как изменились

"Почему уходите с текущего места"
→ Ориентация на рост, а не критика работодателя
→ "Хочу работать с более сложными задачами / технологиями"

"Где видите себя через 5 лет"
→ Senior/Team Lead, экспертиза в [направлении]
→ Ориентируйте на рост, а не на конкретные должности
```

## Технические вопросы Senior Frontend

### JavaScript

```js
// Event Loop — порядок выполнения
console.log('1');           // Sync → 1
setTimeout(() => console.log('2'), 0); // Macrotask
Promise.resolve().then(() => console.log('3')); // Microtask
console.log('4');           // Sync → 4

// Вывод: 1, 4, 3, 2
// Почему: sync → microtasks → macrotasks
```

```js
// Closure — классический вопрос
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// Вывод: 3, 3, 3

// Исправление с let:
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// Вывод: 0, 1, 2
```

### Vue

```
Вопросы, которые часто задают:
- Разница ref vs reactive
- Как работает reactivity system (Proxy)
- watch vs watchEffect
- Жизненный цикл компонента
- Когда использовать provide/inject vs props
- Как оптимизировать производительность
```

### CSS

```
Часто спрашивают:
- Специфичность (specificity) и порядок применения правил
- Как работает BFC (Block Formatting Context)
- Flexbox vs Grid — когда что
- Как центрировать элемент (5 способов)
- CSS custom properties (переменные)
- Стратегии CSS-in-JS vs модули vs BEM
```

## Проведение технического интервью (как интервьюер)

### Структура интервью

```
0-5 мин:   Введение, рассказ о компании и роли
5-20 мин:  Общие вопросы (опыт, стек, проекты)
20-50 мин: Техническая часть (вопросы / кодинг)
50-60 мин: Вопросы кандидата, следующие шаги
```

### Что оценивать

```
Технические навыки (40%):
□ Знание языка и фреймворка
□ Архитектурное мышление
□ Качество кода

Soft skills (40%):
□ Коммуникация (объясняет мышление вслух)
□ Обучаемость (реакция на подсказки)
□ Самостоятельность

Фит с командой (20%):
□ Ценности совпадают
□ Стиль работы
□ Мотивация
```

### Хорошие вопросы для кандидата

```
Вместо тестовых задач "в вакууме" — реальные проблемы:

"Как бы вы организовали state management в приложении с 10+ страницами?"

"У нас есть компонент который ре-рендерится 50 раз за секунду.
Как вы будете дебажить это?"

"Как вы подходите к Code Review? Что проверяете?"

"Расскажите о самом сложном баге, который вы дебажили"
```

## Красные флаги на интервью

### Со стороны кандидата

```
❌ Не может объяснить свой код
❌ "Я никогда не делал ошибок"
❌ Негативно отзывается о прошлых коллегах
❌ Не задаёт вопросов о роли
❌ Не слышит подсказки интервьюера
```

### Со стороны компании

```
❌ Размытое описание роли и задач
❌ Нет кодревью и процессов
❌ "У нас нет техдолга, код чистый"
❌ Неготовность обсуждать зарплату до оффера
❌ Давление ("нам нужно решение сегодня")
```

## Вопросы которые задавать компании

```
О роли:
- Над чем я буду работать в первые 3 месяца?
- Что значит успех для этой позиции?

О команде:
- Как устроен процесс разработки (Scrum/Kanban/другое)?
- Как часто проводятся code review?
- Есть ли возможность менторства?

О технологиях:
- Какой стек используется сейчас?
- Есть ли планы на миграцию/обновление?
- Как управляете техдолгом?

О росте:
- Как выглядит карьерный рост в компании?
- Есть ли бюджет на обучение и конференции?
```
