# Анализ постановки задачи

## Зачем анализировать задачу перед реализацией

```
Без анализа:
Задача → Код → Готово? → Нет, не то → Переделка

С анализом:
Задача → Вопросы → Понимание → Код → Готово ✅
```

Стоимость исправления ошибки в анализе в 10-100 раз дешевле, чем исправление в готовом коде.

---

## Методика разбора задачи

### 1. Прочитать полностью, не приступая к коду

Типичная ошибка: начать писать код при первых 2 строках ТЗ.

### 2. Выявить входные и выходные данные

```
Задача: "Сделать фильтрацию списка товаров по категориям"

Входные данные:
- Список товаров (массив объектов)
- Выбранная категория (строка или null)

Выходные данные:
- Отфильтрованный список товаров
- Количество найденных товаров
```

### 3. Задать уточняющие вопросы

**Шаблон вопросов:**
```
- Что происходит при пустом результате?
- Нужна ли пагинация?
- Множественный выбор категорий или одиночный?
- Фильтрация на клиенте или через API?
- Какой максимальный объём данных?
```

### 4. Определить граничные случаи (edge cases)

```js
// Фильтрация товаров — что если:
items.filter(item => item.category === selectedCategory)

// Edge cases:
// - selectedCategory = null → вернуть все товары
// - items = [] → пустой массив, не ошибка
// - item.category = undefined → что показать?
// - категория с пробелами: "Электроника " vs "Электроника"
```

## Вопросы для уточнения требований

### Функциональные требования
- Что система должна делать?
- Какие сценарии использования (user stories)?
- Кто пользователь? (admin, user, guest)
- Что происходит при ошибке?

### Нефункциональные требования
- Сколько пользователей одновременно?
- Какое время отклика допустимо?
- Нужна ли офлайн-поддержка?
- Какие браузеры/устройства?

### Технические ограничения
- Существующая кодовая база (легаси код)?
- Используемые библиотеки?
- API уже готово или разрабатывается?
- Есть ли дедлайн?

## Пример анализа реальной задачи

**Задача:** "Добавить корзину товаров"

**Вопросы:**
1. Корзина сохраняется между сессиями? (localStorage / сервер)
2. Один товар — несколько штук? Максимум?
3. Удаление из корзины: одна штука или весь товар?
4. Показывать общую сумму? Со скидками?
5. Авторизация обязательна для корзины?
6. Поведение при отсутствии товара (изменение наличия)

**После уточнения:**
```
Корзина:
- Хранится в localStorage (без авторизации)
- Синхронизируется с сервером при логине
- Максимум 99 штук одного товара
- Показывает количество + сумму
- При отсутствии товара — предупреждение
```

## Документирование требований

```markdown
## Задача: Корзина товаров

### Принято к реализации:
- [ ] Добавление товара в корзину
- [ ] Изменение количества
- [ ] Удаление товара
- [ ] Отображение суммы

### Уточнено:
- Хранение: localStorage + синхронизация при логине
- Максимум: 99 штук на позицию

### Вне скоупа (не делаем сейчас):
- Промокоды
- Сохранённые корзины
- Сравнение товаров
```

## Признаки хорошо понятой задачи

- Можете объяснить задачу другому разработчику за 2 минуты
- Знаете все пограничные случаи
- Понимаете, что **не** входит в задачу
- Можете оценить трудозатраты
- Знаете, как проверить что задача выполнена (критерии приёмки)
